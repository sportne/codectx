## Accepted Limitations

The following limitations are accepted for `1.0.0` because they are documented
and consistent with the stable-core contract:

- Java and C++ extraction remain Tree-sitter heuristics, not compiler-perfect semantic analysis.
- Java classpath, generics, annotation processing, and build-tool semantics are not fully resolved.
- C++ templates, macros, overload resolution, include graphs, and build-configuration-specific code are partially understood.
- Call-like and reference edges can remain unresolved and are surfaced as uncertainty.
- SQLite is a rebuildable local cache/artifact, not a storage compatibility contract.
- Real-repo performance thresholds are regression gates, not universal performance promises.

## Decision

The project meets the documented criteria in `06-1.0-release-criteria.md`.
Proceed with a separate `1.0.0` release-candidate preparation task.

That next task should:

- bump `pyproject.toml` and `src/codectx/__init__.py` to `1.0.0`;
- update release examples and tests from `0.2.0` to `1.0.0` where appropriate;
- rerun `make ci` and `make release-ci`;
- create and verify a `release-smoke/v1.0.0-smoke-YYYYMMDDHHMM` tag;
- only after smoke verification, make the explicit production release decision.
